# 계급장 · 초사이언 실루엣 설계

작성일: 2026-08-12
선행: `2026-08-11-ultraman-progress-design.md` (배포 완료, 태그 `v2-progress`)

## 1. 배경

거인화 실루엣이 배포됐지만 형태가 투박하다. 사용자 표현으로 "졸라맨"이다.

원인은 명확하다. **전신을 그렸다.** 팔다리를 선으로 그리는 순간 어떤 파라미터를 조정해도 졸라맨이 된다. 현재 `assets/silhouette.js`의 `figure()`는 머리(원) + 몸통(사다리꼴) + 팔·다리(굵은 선)로 인체를 조립하는데, 이 구성 자체가 한계다.

두 번째 문제는 진행률 표현이다. 실루엣 내부를 아래에서 위로 채우는 방식이라 몸통이 수평선으로 잘려 물통에 담긴 것처럼 보인다.

## 2. 목표

- 졸라맨에서 벗어난다.
- 초사이언 각성처럼 **성장이 시각적으로 읽히게** 한다.
- 8단계에 **조사병단 계급**을 붙여 서사를 준다.
- 한 세션을 완료할 때마다 눈에 보이는 변화가 있어야 한다.

## 3. 비목표

- 외부 이미지·라이브러리 도입 (인라인 SVG 유지, 파일 크기 증가 없음)
- 얼굴·표정 묘사
- 단계 수 변경 (8단계 유지)
- 성취율 정의 변경 (완료 ÷ 36 유지)

## 4. 핵심 결정

### 4.1 전신 → 흉상

팔다리를 그리지 않는다. **머리와 어깨만** 그린다.

초사이언의 상징은 전부 상반신에 있다 — 뻗치는 머리카락, 오라, 번개. 흉상으로 자르면 졸라맨의 원인이 제거되고, 머리카락과 오라가 표현을 전담한다.

### 4.2 수평 채움 → 오라 세기

실루엣 내부를 자르지 않는다. 실루엣은 단계 색을 온전히 입고, **진행률은 오라의 크기·불투명도·번개 굵기**로 표현한다.

```
p = count / 36
```

오라의 크기·불투명도, 번개의 굵기·불투명도가 모두 `p`에 연동된다. 단조 증가한다.

### 4.2.1 한 세션의 변화는 크기가 아니라 개수로 표현한다

`p`만으로는 한 세션의 변화가 전체의 1/36이라 눈에 띄지 않는다. 시안 3에서 13/36과 18/36이 사실상 구분되지 않는 것을 확인했다.

처음에는 `(level/7)*0.62 + inStage*0.38`처럼 단계 기본값과 단계내 진척을 나누는 식을 검토했으나 **폐기했다.** 단계가 바뀌는 순간 `inStage`가 1에서 0으로 떨어져 오라가 급감한다.

```
6/36 (1단계 끝)   → 0.089 + 0.380 = 0.469
7/36 (2단계 시작) → 0.177 + 0.000 = 0.177   ← 오라가 쪼그라든다
```

시안에서 단계 **끝** 지점만 나란히 놓고 비교했기 때문에 놓쳤던 결함이다. 그리고 이는 계수 조정으로 해결되지 않는다. 36단계에 걸쳐 단조 증가하면서 각 단계의 변화가 크려면 단계 폭이 커야 하는데, 한 세션은 본질적으로 전체의 1/36이다. 두 요구는 양립하지 않는다.

**따라서 연속량이 아닌 이산 개수를 쓴다.** 실루엣 주위에 **불티 6칸**을 고정 배치하고, 현재 단계에서 완료한 세션 수만큼 왼쪽부터 채운다.

```
filled = level === 0 ? 0
       : (stage.to > stage.from ? count - stage.from : 6)
```

- 채워진 칸: 금색(`#E8A02C`), 크게
- 빈 칸: 잉크색 13% 불투명도, 작게

크기가 2% 자라는 건 못 봐도 불티 하나가 새로 켜지는 건 확실히 보인다. 빈 칸이 남아 있어 다음 단계까지 몇 세션 남았는지도 함께 읽힌다. 단계가 오르면 6칸이 비워지지만, 동시에 실루엣의 형태·색이 도약하므로 후퇴로 읽히지 않는다.

7단계(완주)는 `stage.to === stage.from`이므로 6칸을 모두 채운다.

### 4.3 계급

| level | 계급 | 단계명 | 완료 수 |
|---|---|---|---|
| 0 | 훈련병 | 인간 | 0 |
| 1 | 신병 | 각성 | 1–6 |
| 2 | 정예병 | 경화 | 7–12 |
| 3 | 분대장 | 변이 | 13–18 |
| 4 | 특무병 | 거인화 | 19–24 |
| 5 | 반장 | 초대형 | 25–30 |
| 6 | 부단장 | 임계 | 31–35 |
| 7 | 단장 | 완전체 | 36 |

기존 단계명은 유지하고 계급을 **추가**한다. 표시는 `분대장 [3단계]` + 아래에 `변이`.

## 5. 그래픽 구성

viewBox `0 0 120 140` 유지.

**흉상** — 어깨는 넓고 낮게, 승모근 경사를 곡선으로 준다(직선 사다리꼴이면 볼링핀이 된다). 어깨 반폭 `30 + level*3.6`, 머리 반지름 `15.5 + level*0.35`.

**머리카락** — 하나의 닫힌 폴리곤. 낱개 바늘이 아니라 덩어리여야 한다(시안 1에서 낱개로 그렸더니 성게가 됐다). 갈래 수 `6 + level`, 길이 `8 + level*5.6`. 왼쪽이 짧고 오른쪽으로 갈수록 길어지며 전체가 오른쪽 뒤로 쓸린다 — 좌우대칭이면 왕관·태양처럼 보인다.

**오라** — 흉상 뒤에 깔리는 채워진 불꽃 실루엣. `radialGradient`로 중심이 진하고 바깥이 투명하다. 크기 `rx = 26 + p*34`, `ry = 44 + p*54`, 불투명도 `0.18 + p*0.62`.

**번개** — level 5부터. 개수 `(level-4)*2 + 1`, 굵기와 불투명도가 `p`에 연동.

**불티** — 흉상 주위 반지름 54의 호에 6칸 고정 배치. 마름모꼴. 4.2.1 참조.

**색** — level별 고정.

```
0 #9A9086  1 #B4441F  2 #BB5220  3 #C56420
4 #D07A22  5 #DC9128  6 #E8AB33  7 #F2C64C
```

무채색에서 러스트를 거쳐 금색으로 간다. 앱 팔레트(`--rust #B4441F`)와 이어진다.

### 알려진 약점

시안 검토에서 확인된 것으로, 구현 중 조정한다.

- 오라가 크림색 배경(`--bg2 #EDE4D2`)에서 대비가 약해 금빛 에너지보다 뿌연 구름으로 보인다. 카드 배경 위에서 확인하고 필요하면 채도·불투명도를 올린다.
- 얼굴이 없는 통실루엣이라 머리는 원으로 남는다. 의도된 단순화다.

### 반투명 겹침 주의

시안 2에서 머리와 머리카락 접합부에 원 테두리가 보였다. 각 도형에 반투명 `fill`을 따로 주면 겹치는 영역이 두 번 칠해지기 때문이다. **그룹에 `opacity`를 한 번만 적용**한다. 현재 설계는 실루엣을 불투명하게 칠하므로 해당되지 않지만, 이후 반투명 레이어를 추가할 때 다시 발생할 수 있다.

## 6. 영향 범위

| 파일 | 변경 |
|---|---|
| `assets/logic.js` | `STAGES` 각 항목에 `rank` 추가 |
| `assets/silhouette.js` | `figure`/`figureMarkup`/`silhouetteSVG` 교체, `stageSheetHTML`에 계급 표시 |
| `assets/app.js` | 홈 상태 카드에 계급 배지 |
| `index.html` | 계급 배지 CSS |
| `test/logic.test.js` | `rank` 검증 추가 |

`silhouetteSVG(count)`와 `stageSheetHTML(count)`의 시그니처는 바뀌지 않으므로 `app.js`의 호출부는 그대로다.

**유지해야 할 기존 동작 둘.**

- `clipPath` 고유 id 카운터 — 화면 전환 중 두 실루엣이 300ms 겹칠 때 id가 중복되면 잘못된 값을 참조한다. 수평 채움을 없애면 `clipPath` 자체가 사라지지만, `radialGradient` id에 같은 문제가 생기므로 **카운터를 그라디언트 id로 옮긴다.**
- `progress`·`stageOf` 계약 불변.

## 7. 검증

- `node --test` — `STAGES`가 8개이며 각각 `rank`를 갖는지, 0–36 전 구간을 빈틈없이 덮는지.
- `silhouetteSVG`를 0–36 전 구간에서 호출해 well-formed XML인지, 두 번 호출하면 그라디언트 id가 다른지.
- **오라 크기가 0→36 전 구간에서 단조 비감소인지.** 단계 경계(6→7, 12→13, 18→19, 24→25, 30→31, 35→36)를 반드시 포함한다. 폐기한 공식이 정확히 여기서 깨졌다.
- 불티 채움 수가 단계 시작에서 0, 단계 끝에서 6(또는 마지막 단계는 항상 6)인지.
- 헤드리스 Chrome으로 8단계와 단계내 진행을 렌더해 육안 확인. 시안(`scratchpad/mock/mock4.html`)과 대조한다.
- 배포 URL에서 최종 확인.
